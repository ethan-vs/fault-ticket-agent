# 引用归属问题的修正闭环

## BC-CITE-001

**场景：** 先查询TK-002，再改为分析TK-001。

**修正前：**

> 工单TK-001记录的事实：多台电脑无法连接Wi-Fi、有线可用，相关设备AP-01，状态待处理。……[RULE-NET-001@1.0#001]

**问题：** 工单编号、设备和状态来自 `get_ticket`。规范能支持排查方法，不能证明某张工单的事实。引用存在、摘录合法，并不意味着它支持附近所有句子。

**修改：**

1. 提示词要求先写工单事实、说明来源，再另起段落写资料建议。
2. 评测器增加启发式筛查，标记带工单编号或设备的事实段混挂规范引用。
3. 增加“旧错误输出应被标记”和“来源分开应被允许”的回归用例。
4. 重新执行E05并复核实际回答。

**修正后：** 工单事实段明确标注 `get_ticket`，不再挂规范片段；规范引用放在检查建议后，模拟案例仅作可能性提示。

**剩余限制：** 筛查依赖段落格式和明确的事实标记，不会识别所有隐含事实或语义错误，仍需人工复核。一次重跑成功也不能证明问题永久消失。

## ENV-CONNECTION-001

E05首次请求发生APIConnectionError，未查询工具。报告保留请求尝试与异常类型，重跑成功后仍保留原记录。现有证据只足以定位为连接错误，不能断言是代理、DNS或服务商故障。
